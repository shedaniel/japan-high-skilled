# Data, generation, and storage

This document describes how the calculator's data is organized, how the
university dataset is generated, how qualifications are cataloged, and how the
browser profile is persisted. Policy rules and their sources live in
[docs/POLICY.md](POLICY.md).

## Directory map

| Path | Role |

## Data flow

```text
src/domain/policy.ts
        |
        v
src/lib/calculator.ts  <----  Profile (UI state + localStorage)
        |                         ^
        v                         |
   ScoreResult  ---------->  score breakdown UI

src/data/universities/generated.json
        |
        v
src/data/universities/index.ts (validation, maps)
        |
        v
UniversityPicker -> profile.education.* -> calculator bonuses

src/data/qualifications/*.ts
        |
        v
src/data/qualifications/index.ts
        |
        v
QualificationPicker -> profile.japanQualifications / foreignQualifications
        |
        v
calculator qualification and foreign-bonus logic
```

The policy constants are imported by the calculator, not copied into
components. The pickers do not mutate the profile; the parent maps a selection
into `profile.education` or the qualification arrays.

## University dataset

### Envelope

`generated.json` has this top-level shape:

```json
{
  "meta": {
    "generatedAt": "YYYY-MM-DD",
    "sources": {
      "ranking": {
        "url": "https://...",
        "title_en": "...",
        "title_ja": "...",
        "as_of": "YYYY-MM"
      }
    },
    "counts": {
      "total": 0,
      "japan": 0,
      "designated": 0
    }
  },
  "universities": []
}
```

`meta.sources` has one entry for each source tag: `ranking`, `sgu`,
`innovative-asia`, and `japanese-mext`. `meta.counts.designated` counts records
with at least one of `ranking`, `sgu`, or `innovative-asia`.

### University record schema

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `id` | string | Yes | Stable ID in the form `u-` followed by 10 lowercase hexadecimal characters. |
| `nameEn` | string | Yes | English institution name. |
| `nameJa` | string | Yes | Japanese institution name. Non-empty for every record. |
| `countryEn` | string | Yes | English country name. |
| `countryJa` | string | Yes | Japanese country name. |
| `isJapan` | boolean | Yes | Drives the Japan-degree bonus. `true` implies `countryEn` is `Japan`. |
| `sources` | `UniversitySource[]` | Yes | Non-empty subset of `ranking`, `sgu`, `innovative-asia`, `japanese-mext`. |
| `institutionType` | `"national" \| "public" \| "private"` | No | Set from the MEXT directory. Optional in the type; not every Japanese record has it. |

`UniversityRecord` in `src/domain/types.ts` mirrors this schema. The loader
(`src/data/universities/index.ts`) validates required strings, the boolean
flag, source tags, and optional institution types at import time. It throws on
duplicate IDs, malformed metadata, or a missing `ranking` source. The ranking
source URL is re-exported as `OFFICIAL_UNIVERSITY_LIST_URL`.

### Sources and parsers

| Source tag | Document | Parser |
| --- | --- | --- |
| `ranking` | Immigration Services Agency designated-university list (January 2026 PDF) | `parse_ranking` with `pdfplumber` table extraction; expects name, Japanese name, and `Country / 国` columns. |
| `sgu` | MEXT Super Global University project | Hard-coded `SGU` list in the script. |
| `innovative-asia` | MOFA Innovative Asia partner universities | Hard-coded `INNOVATIVE_ASIA` list in the script. |
| `japanese-mext` | MEXT national university directory (2026) | `parse_mext` with `openpyxl`; one row per worksheet, institution type from the sheet title. |

The script download URLs and as-of labels are the `SOURCES` dictionary at the
top of `scripts/build-universities.py`. MEXT workbook URLs are hard-coded to
the 2026 directory: one national workbook, one public workbook, and private
workbooks 1 through 8. The SGU list currently has 38 entries, including both
pre-merger and post-merger Tokyo institutions. The Innovative Asia list has 64
entries.

### Merge rules

1. Build a merge key from the Japanese name when present, otherwise the
   English name.
2. Normalize the key by removing whitespace (including the full-width space),
   `()`, `（）`, `・`, `,`, `，`, `.`, and `．`, then lowercasing.
3. For ranking records only, remove a `（統合前…）` or `(Previously: …)`
   annotation before building the key, so a current name joins the MEXT entry.
4. The first record for a key seeds the result. Missing English names are
   filled from later records; `institutionType` is copied when a MEXT record
   contributes; a `true` Japan flag forces `countryEn`/`countryJa` to Japan.
5. Source tags are unioned without duplicates, preserving first-seen order
   (the ranking pass runs first, then SGU, Innovative Asia, and MEXT).
6. Assign `id = "u-" + sha1(normalized key)[:10]`.
7. Sort by `nameEn` ascending with empty names last (`zzz` fallback), then by
   `nameJa`.

The output is UTF-8 JSON with `ensure_ascii=False`, two-space indentation, and
a trailing newline. `meta.generatedAt` is `date.today()` at generation time, so
every regeneration changes at least that line.

### Stable IDs

IDs are derived from names, not from an external registry. A rename, a merger,
or a script change to normalization can produce a new ID. Profiles store the ID
together with the university names and source tags; the copied names and bonus
flags remain usable if an ID disappears, but a lookup by ID will fail. Do not
rename IDs by hand.

### Running the generator

Requirements:

- Python 3.9 or newer (the script uses built-in generic annotations).
- Network access on the first run.
- `pip install -r scripts/requirements.txt`, which pins `pdfplumber==0.11.9`
  and `openpyxl==3.1.5`.

```bash
python3 -m pip install -r scripts/requirements.txt
pnpm data:universities
```

`pnpm data:universities` runs `python3 scripts/build-universities.py`. The
script writes `src/data/universities/generated.json`; the web app has no
runtime network dependency because the JSON is imported at build time.

Caching:

- Downloads go to `scripts/.cache/<name>.<suffix>`.
- A cached file is reused when it exists and is larger than 1,000 bytes.
- Delete the relevant cache file, or the whole `scripts/.cache/` directory, to
  force a fresh download.
- The cache is a local build artifact. Do not commit it.

### Review checklist after regeneration

1. Read `meta.generatedAt` and each `meta.sources[*].as_of`; confirm the source
   editions are the intended ones.
2. Confirm the diff is limited to plausible additions, removals, and source
   tag changes. A large churn in names or countries usually means a parser
   assumption broke.
3. Verify `meta.counts.total`, `japan`, and `designated` match the arrays.
4. Check for duplicate or unexpectedly split names, especially after
   university mergers. The SGU list intentionally contains both pre-merger and
   post-merger Tokyo entries.
5. Spot-check a small set of well-known Japanese and foreign institutions
   against the official PDFs.
6. Confirm every designated record has at least one of `ranking`, `sgu`, or
   `innovative-asia`, and that `japanese-mext` appears only on Japanese
   records.
7. Run `pnpm test` and `pnpm typecheck`.
8. If a source URL or as-of date changed, update the source metadata in the
   script so the regenerated JSON records it, and update
   [docs/POLICY.md](POLICY.md).

**Never hand-edit `src/data/universities/generated.json`.** The next run
overwrites it, and manual edits bypass the merge and ID rules.

## Qualification catalogs

### Record schema

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `id` | string | Yes | Stable identifier, unique across all catalogs. Prefixes are `jp-`, `it-`, and `f-` by convention. |
| `nameEn` | string | Yes | English name. |
| `nameJa` | string | Yes | Japanese name. |
| `kind` | `"japan-national" \| "it-exam" \| "foreign"` | Yes | Catalog kind. |
| `category` | `QualificationCategory` | Yes | One of the values in `QUALIFICATION_CATEGORIES`. |
| `country` | `{ en: string; ja: string }` | No | Set for foreign qualifications and designated foreign IT exams. |
| `note` | `{ en: string; ja: string }` | No | Optional explanatory note. |

Each catalog file uses a small constructor:

| File | Constructor | Export |
| --- | --- | --- |
| `japan-national.ts` | `q(id, nameJa, nameEn, category)` | `JAPAN_NATIONAL_QUALIFICATIONS` |
| `it-exams.ts` | `it(id, nameJa, nameEn, countryEn?, countryJa?)` | `IT_EXAMS` |
| `foreign.ts` | `f(id, nameJa, nameEn, category, countryEn?, countryJa?)` | `FOREIGN_QUALIFICATIONS` |

`src/data/qualifications/index.ts` composes:

- `JAPAN_QUALIFICATIONS` = national + IT exams (153 records in the current
  snapshot: 89 national and 64 IT).
- `ALL_QUALIFICATIONS` = Japan + foreign (225 records; 72 foreign).
- `QUALIFICATIONS_BY_ID` = a map over all records.
- `QUALIFICATION_CATEGORIES` = `legal`, `accounting`, `real-estate`,
  `medical`, `welfare`, `education`, `engineering`, `construction`, `it`,
  `safety`, `service`, `design`, `fashion`, `actuarial`.

Only `JAPAN_QUALIFICATIONS` earns the 5/10-point 1号ロ bonus. Only
`FOREIGN_QUALIFICATIONS` earns the foreign 5-point bonus. The calculator
deduplicates IDs with `Set` before counting.

### Adding a qualification

1. Choose the catalog and constructor: national qualification, IT告示 exam, or
   foreign qualification/award.
2. Add a unique, stable ID. Do not reuse an ID for a different qualification;
   saved profiles reference IDs.
3. Provide both Japanese and English names. The data-integrity tests reject
   empty names and duplicate normalized names within a kind.
4. Use an existing category. The category must be a member of
   `QUALIFICATION_CATEGORIES`.
5. For foreign records and designated foreign IT exams, supply the country
   when known. `LocalizedText.country` accepts `en`, `ja`, and an optional
   `zhHant`; the data-integrity test requires a non-empty `zhHant` value.
6. If the official source revision date changes, update the source note in
   `docs/POLICY.md` and the catalog comment.
7. Run `pnpm test` and `pnpm typecheck`.

### Adding a category

1. Add the identifier to `QUALIFICATION_CATEGORIES` in
   `src/data/qualifications/index.ts`. The exported
   `QualificationCategory` type updates automatically.
2. Add `qualification.category.<id>` to the English and Japanese objects in
   `src/i18n/messages.ts` and to `src/i18n/messages.zh-Hant.ts`.
   `MessageKey` is derived from the English keys, and every other catalog is
   typed as `Record<MessageKey, string>`, so a missing translation is a type
   error and `src/i18n/i18n.test.ts` fails on a key-set mismatch.
3. If the category needs a picker filter, add the corresponding
   `qualification.filter.*` key and UI wiring. The picker groups by category
   using the existing label keys.
4. Add at least one record to a catalog so the category is reachable, then run
   the tests.

### Custom entries

The qualification picker can add a user-entered Japanese qualification that is
not in the catalog.

- ID format: `custom-${crypto.randomUUID()}`.
- Shape: `{ id, nameJa, nameEn }`.
- The parent app appends the entry to both `profile.customQualifications` and
  `profile.japanQualifications`.
- Removing it must remove it from both arrays.
- It counts toward the 5/10-point Japanese qualification total.
- It never counts as a foreign qualification.
- The app does not verify that the custom entry is a 業務独占 or 名称独占
  qualification, or that it relates to the work. The user attests; the
  immigration office decides.

### i18n keys

Qualification and university UI text uses flat keys in
`src/i18n/messages.ts`. Every key must exist in all three catalogs:
`src/i18n/messages.ts` (English and Japanese) and
`src/i18n/messages.zh-Hant.ts` (Traditional Chinese). The relevant groups are:

| Group | Examples |
| --- | --- |
| Qualification labels and rules | `qualification.japanNational`, `qualification.foreign`, `qualification.rule.japan`, `qualification.rule.foreign` |
| Search and selection | `qualification.search`, `qualification.empty`, `qualification.selectedCount`, `qualification.pointsPreview`, `qualification.maxReached` |
| Categories | `qualification.category.<category>` for all 14 categories |
| Custom entries | `qualification.other`, `qualification.otherHint`, `qualification.addCustom`, `qualification.addCustomHint`, `qualification.custom`, `qualification.removeCustom` |
| Filters | `qualification.filter.all`, `qualification.filter.japan`, `qualification.filter.foreign` |
| University source badges | `university.sources.ranking`, `university.sources.sgu`, `university.sources.innovative-asia`, `university.sources.japanese-mext` |
| University list copy | `university.listAsOf`, `university.total`, `university.designatedSources`, `university.officialList`, `university.notDesignated` |
| Band dropdown options | `option.age.*`, `option.career.*`, `option.salary.*`, `option.bjt.*`, `option.unspecified` |
| Language switch | `nav.localeEnglish`, `nav.localeJapanese`, `nav.localeTraditionalChinese` |

If a new university source tag is added, update `UniversitySource` in
`src/domain/types.ts`, the loader's allowed-source list, the build script, the
badge key, and this document. The loader rejects unknown tags at import time.

## Local storage

### Keys

| Key | Value | Version |
| --- | --- | --- |
| `hsp-points-profile:v1` | JSON-serialized `Profile` | `version: 1` inside the value and `:v1` in the key |
| `hsp-points-locale` | `"en"`, `"ja"`, or `"zh-Hant"` | Unversioned |

The profile key is defined in `src/lib/storage.ts`. The locale key is separate
so resetting the calculator keeps the language choice.

### Profile shape

The full type is `Profile` in `src/domain/types.ts`. Top-level fields:

| Field | Type | Notes |
| --- | --- | --- |
| `version` | `1` | Forced to 1 by `normalizeProfile`. |
| `activity` | `"academic" \| "specialized" \| "management"` | Selects the point tables. |
| `age` | `number \| null` | Age band representative (29, 32, 37, 45) or `null`. |
| `annualSalaryManYen` | `number \| null` | Salary band lower bound in 万円 (0, 300, 400, … 3000) or `null`. |
| `careerYears` | `number \| null` | Career band representative (0, 3, 5, 7, 10) or `null`. |
| `education` | object | Highest level, MBA/MOT and multiple-degree flags, selected university ID/names/country/sources, and the two bonus flags. |
| `research` | object | Four booleans: `patent`, `grant`, `papers`, `other`. |
| `position` | `"representative" \| "director" \| "none"` | Used only for ハ. |
| `japanQualifications` | `string[]` | Catalog IDs plus custom IDs. |
| `foreignQualifications` | `string[]` | Catalog IDs; never custom IDs. |
| `customQualifications` | `{ id, nameJa, nameEn }[]` | Mirrors the custom IDs in `japanQualifications`. |
| `language` | object | `jlpt`, `bjtScore`, `japaneseMajor`. |
| `bonuses` | object | Eight booleans for the special-bonus checkboxes. |

The university selection also copies `universityNameEn`, `universityNameJa`,
`universityCountryEn`, `universityCountryJa`, and `universitySources` into
`education`. The copied values keep the summary readable if the dataset
changes; `designatedUniversity` and `japaneseInstitution` are the flags the
calculator actually scores.

### Load, save, merge, and reset

- On mount, `loadProfile()` reads the key. Invalid JSON or storage failure
  returns `createDefaultProfile()`.
- `normalizeProfile()` starts from the default profile, merges known nested
  sections, forces `version: 1`, filters `japanQualifications` and
  `foreignQualifications` to strings, and filters `customQualifications` to
  objects with string `id`, `nameJa`, and `nameEn`. It does not perform version
  migrations; there is no v0 schema.
- The hook skips the save on its first render, then saves the whole profile on
  every change. Save failures (private mode, quota, unavailable storage) are
  swallowed so the calculator keeps working.
- The `storage` event reloads the profile when another tab writes the same
  key. Locale changes are not synchronized by this hook.
- `reset()` removes the profile key, replaces the state with the default
  profile, and updates `savedAt`. It does not remove `hsp-points-locale`.
- `savedAt` is in-memory only and is not part of the stored JSON.
- Export produces the same `Profile` JSON with a two-space indent and the
  filename `hsp-points-profile-v1.json`. Import requires an object with
  `version: 1` and passes it through `normalizeProfile`; unsupported versions
  and non-object payloads are rejected.

If the profile schema changes incompatibly, introduce a new key version or add
an explicit migration. Do not silently reinterpret an existing `version: 1`
payload.

## Validation

Run these after data or calculator changes. Do not run them while another agent
is mid-edit.

| Command | Purpose |
| --- | --- |
| `pnpm test` | Runs the Vitest suite once, including calculator and data-integrity tests. |
| `pnpm typecheck` | Runs the TypeScript project build without emitting. |
| `pnpm build` | Type-checks and produces the production bundle. |
| `pnpm lint` | Runs Oxlint. |
| `pnpm data:universities` | Regenerates the university JSON. Review the diff before committing. |

`src/data/data-integrity.test.ts` checks:

- University IDs are unique and `UNIVERSITY_BY_ID` resolves each record by
  identity.
- Every university has a non-empty Japanese name.
- Source tags are known, every designated record has a designation source, and
  `japanese-mext` appears only on Japanese records.
- Non-designated records are Japanese MEXT directory entries.
- Dataset size thresholds and `meta.counts` consistency.
- Every source has an HTTPS URL and non-empty English, Japanese, and
  Traditional Chinese titles.
- All three message catalogs expose the same key set, and every interpolation
  placeholder matches across locales.
- Qualification IDs are unique across catalogs, the catalog lengths compose
  correctly, names are non-empty, kinds match their catalog, no duplicate
  normalized names exist within a kind, and the ID map resolves every record.

### Additional JSON checks

For a quick check outside Vitest, this mirrors the main university invariants:

```bash
python3 - <<'PY'
import json
import re
from pathlib import Path

data = json.loads(Path("src/data/universities/generated.json").read_text())
universities = data["universities"]
ids = [record["id"] for record in universities]
allowed = {"ranking", "sgu", "innovative-asia", "japanese-mext"}
designated = {"ranking", "sgu", "innovative-asia"}

assert len(ids) == len(set(ids)), "duplicate university id"
assert all(re.fullmatch(r"u-[0-9a-f]{10}", value) for value in ids)
assert all(record["nameJa"] and record["nameEn"] for record in universities)
assert all(record["sources"], "empty sources")
assert all(set(record["sources"]) <= allowed, "unknown source")
assert all(
    record["isJapan"] == (record["countryEn"] == "Japan")
    for record in universities
), "Japan flag and country disagree"

counts = data["meta"]["counts"]
assert counts["total"] == len(universities)
assert counts["japan"] == sum(record["isJapan"] for record in universities)
assert counts["designated"] == sum(
    bool(set(record["sources"]) & designated) for record in universities
)
print("university data ok:", counts)
PY
```

The loader performs the same structural checks at runtime and will fail the
build on a malformed committed file, so a successful `pnpm build` is also a
data validation signal.
